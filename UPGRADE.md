# Expo SDK 33 → 56 Upgrade

This app was migrated from **Expo SDK 33 (detached / ExpoKit, RN 0.59, React 16)**
to **Expo SDK 56 managed workflow (RN 0.85, React 19.2)**.

> **Verified so far (Linux container, no Xcode):**
> - `npm install` — clean, no peer-dependency conflicts.
> - `npx expo-doctor` — **21/21 checks pass**.
> - `npx expo export --platform ios` — Metro bundles **all** JS into a Hermes
>   bundle with no resolution/transform errors (exercises the icon shim,
>   `expo-web-browser`, `react-native-safe-area-context`, and the vendored
>   search bar).
>
> **Still requires a Mac (can't run here):** actual native iOS compile via
> `expo prebuild` + Xcode or `eas build`, and on-device/simulator runtime
> testing — including the Ionicons glyph audit in [§4](#4-known-follow-ups).
> Package versions are the exact SDK 56 pins (no longer placeholders).

## 1. Why this isn't a version bump

SDK 33 was **detached via ExpoKit** (`isDetached: true`, `expokit`,
`react-native-unimodules`, a committed `ios/` shell app). Expo removed ExpoKit and
unimodules years ago. Modern Expo has two workflows — **managed** (native projects
generated on demand by `expo prebuild` / EAS) and **bare** (native dirs committed).
We chose **managed**, because the app has **no custom native code** — its JS only
uses `expo-font`, `expo-linear-gradient`, and `expo-web-browser`, all first-class
managed modules.

## 2. What changed in this PR

### Project config
- **`package.json`** — rewritten for SDK 56. Removed `expokit`,
  `react-native-unimodules`, `react-native-dynamic-vector-icons`,
  `react-native-linear-gradient` (unused — code already used `expo-linear-gradient`),
  and the ancient pinned eslint/jest/babel toolchain. Added `@expo/vector-icons`
  and `react-native-safe-area-context`. `main` now points at `index.js`.
- **`app.json`** — stripped all ExpoKit/detached keys (`isDetached`, `detach`,
  `sdkVersion`, `publishBundlePath`/`publishManifestPath`, the random `scheme`,
  ExpoView S3 URLs). Added managed-workflow keys (`newArchEnabled`,
  `assetBundlePatterns`, clean `scheme`).
- **`index.js`** — uses `registerRootComponent` from `expo` instead of
  `AppRegistry.registerComponent`.
- **`rn-cli.config.js`** — deleted (obsolete Metro config name; Expo's default
  Metro config already resolves `.jsx`).
- **`ios/`** — the 440 MB ExpoKit shell (including committed CocoaPods) was
  removed. Native projects are now generated by `expo prebuild` and git-ignored.
- **`.gitignore`** — updated to the standard Expo managed ignore set.

### Code fixes for removed/changed APIs
- **`expo` umbrella imports are gone.** `import { WebBrowser } from "expo"` →
  `import * as WebBrowser from "expo-web-browser"` (`StickerDetails.jsx`).
- **Vector icons.** `react-native-dynamic-vector-icons` (dead) → `@expo/vector-icons`
  via a small compat shim, **`components/Icon.js`**, that preserves the old
  `<Icon name type size color />` prop shape (where `type` is the icon family).
  Re-pointed the three importers (`StickerDetails.jsx` and the vendored search
  bar's `SearchIcon.js` / `SearchCancel.js`).
- **SafeAreaView.** `react-native`'s `SafeAreaView` is deprecated/removed in RN
  0.85 → now imported from `react-native-safe-area-context`, and the tree is
  wrapped in `<SafeAreaProvider>` (`App.js`).

## 3. Required steps on a real machine

Dependency versions are already the exact SDK 56 pins (taken from
`expo/bundledNativeModules.json`), `expo-doctor` is green, and the JS bundles.
Remaining steps need macOS:

```bash
cd requestion-react-native
npm install
npx expo start             # smoke test in Expo Go / dev client (Mac or device)
```

To produce native builds (managed → no committed native dirs):

```bash
npx expo prebuild          # regenerates ios/ (and android/) locally, if needed
# or, preferred:
eas build -p ios           # cloud build via EAS
```

## 4. Known follow-ups (need a running app to verify)

- **Ionicons glyph names.** This app targeted Ionicons v4; names changed in v5+.
  `ios-share-alt` (in `StickerDetails.jsx`) no longer exists and will render as a
  missing glyph — likely `share-social-outline` now. Audit each `Ionicons` name
  once the app runs. (`logo-instagram`, `arrow-back` (MaterialIcons) are fine.)
- **Vendored search bar** (`components/react-native-dynamic-search-bar`) still
  depends on `react-native-iphone-x-helper`; kept as a dependency. Consider
  replacing it with `react-native-safe-area-context` insets later.
- **`InputAccessoryView`** is iOS-only (the app is iOS-only, so fine).
- **New Architecture** is enabled (`newArchEnabled: true`); verify the vendored
  search bar and gradient render correctly under it.
